# Crossover Explorer

The **crossover explorer** is an application that filters and displays SNPs, with the goal of looking for evidence of crossover and non-crossover events in _C. elegans_ genomes.

The application, named `xo`, is run from the command line.
To run it, open a terminal window and type `xo CMND` where CMND is the name of the operation you want to perform.

Three of those operations (`peaks`, `filter`, and `post`) apply various filtering operations and save their outputs in CSV files.

The fourth command, `gui`, uses a graphical user interface that lets users experiment with filter values and see the effects interactively.

See [Command Line API](api.md) for instructions on using the main `xo` command.


## Data Files

The application uses two sets of data:

* `BSP_TIGER.marker_dataframe.pickle.gzip` is a "pickled" and compressed Pandas data frame with the output from TIGER.  Each row in the frame describes a SNP, with columns for the
chromosome name, location, and the predicted parent genome (N2 or CB4856), and more.

* `BSP_TIGER.intervals_dataframe.pickle.gzip`, a summary of the SNP data, where each row defines a chromosome segment and its predicted parent.

We suggest creating a new folder to use for a project directory.  Move (or link) the two data files to this folder, then `cd` to the directory and run the crossover explorer scripts in that directory.

> **Note for Docker users**:  if you are running the GUI in a Docker container you will bind mount this same directory when starting the container.

## Candidate Blocks

The first step in finding potential noncrossovers uses a "peak finder" to scan the SNPs generated by TIGER to look for chromosomal regions that might be the result of crossover or non-crossover events. 
We call these regions **blocks**.

The peak finder is run by typing a shell command.
It will generate a CSV file (by default named `peaks.csv`) that will be used in the later steps.

See [Find Peaks](peaks.md) for instructions on running the shell command.


## Exploring Crossovers with the GUI

The graphical user interface displays one chromosome at a time.
A plot at the top of the window shows the chromosome as a horizonal bar with black dots superimposed to show the locations of the blocks that were found in the chromosome.
Below that is a section with that displays more detailed information about the SNPs in each block.

The left side of the GUI has a set of controls that let the user specify various filtering criteria, such as block size (number of SNPs in a block) or block length (distance, in bp, between the first and last SNP in a block).

Each time a control is changed the GUI is updated to show only the blocks that satisfy all the filtering critera.

See [View SNPs](gui.md) for instructions on starting the GUI and using the filters.

## Applying Filters from the Command Line

The filtering criteria implemented in the GUI can also be applied from the command line.

There are two filtering commands.

- The first command (`filter`) applies block size and block composition filters.
It reads the CSV file generateed by the peak finder, applies the filters, and writes the results to another CSV file (by default named `filtered.csv`).

- The second command (`post`) is a postprocessing step that searches for NCOs inside filtered blocks.
It uses an additional set of filtering criteria to identify the single best candidate NCO inside each block.
This command reads the CSV file with filtered blocks, applies the postprocessing algorithm, and writes the result to another CSV file (by default named `post.csv`).

Both of the commands have arguments that correspond to the fitering controls in the GUI.
For example, the GUI has a slider to specify minimum and maximum block size (number of SNPs in a block).
The `filter` command has an option named `--size` for defining the same settings.

The two commands are described in more detail in [Filter Blocks](filter.md) and [Identify NCOs](post.md).
